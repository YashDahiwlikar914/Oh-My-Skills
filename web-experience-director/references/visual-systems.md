# Visual Systems

## Start With A Premise

A visual premise is a specific constraint that connects the subject matter to the interface. It is not a style label.

| Weak Direction | Usable Direction |
| --- | --- |
| Make it premium and futuristic | Treat a watch viewer as a precision instrument with controlled light, close material study, and measured labels |
| Make the portfolio immersive | Treat the portfolio as a contact sheet becoming a photographic sequence with crop marks, paper layers, and quiet captions |
| Make the dashboard modern | Treat the dashboard as a calm daily ledger where the next decision is more visible than decoration |

Choose one premise and let it guide type, image treatment, palette, surface, space, and motion. Do not copy several unrelated trends into the same page.

## Establish Hierarchy Before Effects

Write the reading order for each view. Decide what must be seen immediately, what supports it, and what can stay secondary. Give the primary action a clear visual route.

- Headings should name the product value or next decision.
- Supporting copy should reduce uncertainty rather than repeat the heading.
- Image, color, contrast, scale, and whitespace should reinforce the same order.
- Dense work screens need faster scanning than marketing pages. Prefer grouping, labels, summaries, and restrained emphasis over decoration.
- Forms and purchases need stable labels, errors near the field, clear state changes, and no motion that hides completion.

## Compose For The Actual Content

Use real copy, names, images, data, and empty states early. A layout that only works with short placeholder text is not ready.

Build desktop and mobile compositions separately. On mobile, decide whether the image, title, action, and supporting information need a different order. Remove decorative depth before reducing readable content.

Keep a protected reading zone around text and controls. Changing imagery, video, or a WebGL scene must not make important text unreadable from one frame to the next.

## Type, Color, And Surface

Typography gives an interface rhythm before any animation starts. Select families for their role, then use size, width, leading, and contrast deliberately. Avoid a display face that fights the content or a body face that becomes hard to scan.

Use color to establish hierarchy and state. Do not rely on color alone for status, selection, validation, or meaning. A material such as paper, lacquer, brushed metal, stone, or soft plastic is useful only when it belongs to the premise and remains readable in every state.

## Direction Review

Ask these questions before moving into motion or 3D.

| Question | Pass Condition |
| --- | --- |
| Can the premise be named in one sentence | It refers to the product and concrete visual decisions |
| Does the primary task still dominate | A screenshot makes the main action and content clear |
| Do type, imagery, palette, and layout agree | No element feels imported from a different visual system |
| Does the design work without animation | The page remains understandable and intentional |
| Does mobile have its own composition | It is not a squeezed desktop screenshot |

## Common Failures

- A generic dark void with colored light that has no relation to the product
- Glass surfaces layered until text contrast and hierarchy disappear
- Large type used as decoration while the actual product value stays vague
- Every section using the same card grid and reveal animation
- Visual references copied by surface details without their content structure or rhythm
